# 3.4 Sub-agents and Parallel Execution (서브에이전트와 병렬 실행)

서브에이전트는 메인 러너가 복잡하거나 오래 걸리는 작업을 격리된 백그라운드 러너에 위임하는 메커니즘이다. 구현은 `nanobot/agent/subagent.py`, 노출 도구는 `nanobot/agent/tools/spawn.py`의 `SpawnTool`이다.

## `SubagentManager`

```python
SubagentManager(provider, workspace, bus, max_tool_result_chars,
                model=None, tools_config=None, restrict_to_workspace=False,
                disabled_skills=None, max_iterations=None,
                max_concurrent_subagents=None, fail_on_tool_error=None,
                llm_wall_timeout_for_session=None)
```

- 자체 `AgentRunner`(`self.runner`)를 가진다 — 서브에이전트도 같은 러너 루프를 쓴다.
- 실행 상태를 추적한다: `_running_tasks`(task_id → asyncio.Task), `_task_statuses`(task_id → `SubagentStatus`), `_session_tasks`(session_key → task_id 집합).
- 동시 실행 수는 `max_concurrent_subagents`(설정 `agents.defaults.maxConcurrentSubagents`, 기본 1)로 제한된다.

### 격리된 도구 세트

서브에이전트는 축소된 도구 레지스트리를 받는다.

- `_subagent_tools_config()` — `exec`, `web`, `file`과 `restrict_to_workspace`만 포함한 `ToolsConfig`를 만든다(예: message/spawn 같은 도구는 제외해 무한 중첩·채널 전송을 막음).
- `_build_tools(workspace, tools_config)` — 독립 `ToolRegistry`를 만들고 `ToolLoader().load(ctx, registry, scope="subagent")`로 로드. `ToolContext`에는 워크스페이스 샌드박스 상태(`workspace_sandbox_status`)가 붙는다([11.2](11.2-workspace-policy-and-sandboxing.md)).

## 스폰과 실행

- `spawn(task, label, origin_channel, origin_chat_id, session_key, ...)` — 새 서브에이전트 태스크를 등록하고 asyncio 태스크로 실행. `SpawnTool.execute`가 이를 호출한다.
- `_run_subagent(...)` — 서브에이전트용 시스템 프롬프트(`_build_subagent_prompt`, 템플릿 `nanobot/templates/agent/subagent_system.md`)로 러너를 돌린다.
- 진행 상황은 `_SubagentHook`(`AgentHook` 서브클래스)이 추적해 `SubagentStatus`를 갱신한다(`before_execute_tools`, `after_iteration`).
- 완료 시 `_announce_result(...)`가 결과를 원래 채널/세션으로 알린다(템플릿 `subagent_announce.md`). `_format_partial_progress`는 미완 진행을 요약.

## 상태 조회와 취소

- `SubagentStatus` — 태스크 상태 스냅샷.
- `get_running_count()`, `get_running_count_by_session(session_key)` — 실행 수 조회.
- `cancel_by_session(session_key)` — 세션에 묶인 서브에이전트 일괄 취소(예: 사용자가 `/stop` 또는 새 메시지를 보낼 때, `AgentLoop._cancel_active_tasks`와 연동).
- `set_provider(provider, model)` — 런타임 모델 전환 시 서브에이전트 프로바이더도 갱신([3.1](03.1-agent-loop-and-turn-state-machine.md)의 `_sync_subagent_runtime_limits`).

## `SpawnTool` (`nanobot/agent/tools/spawn.py`)

- `Tool`이면서 `ContextAware`다 — `set_context(ctx)`로 현재 요청 컨텍스트(채널, chat_id, session_key)를 받는다.
- `execute(...)`는 매니저의 `spawn`을 호출해 작업을 백그라운드로 위임하고, 즉시 사용자에게 위임 사실을 알린다.

## 자기 상태 점검과의 관계

`my` 도구(`nanobot/agent/tools/self.py`)의 상태 포매터(`_format_status`)는 `SubagentStatus`를 렌더링해, 에이전트가 자신의 서브에이전트 진행 상황을 조회할 수 있게 한다([6.3](06.3-cron-image-generation-and-other-tools.md)).
