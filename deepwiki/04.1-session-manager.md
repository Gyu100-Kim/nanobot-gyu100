# 4.1 Session Manager (세션 매니저)

세션 관리는 `nanobot/session/manager.py`의 두 클래스가 담당한다: 개별 대화 상태인 `Session`과, 디스크 영속성을 관리하는 `SessionManager`.

## 세션 키 (`nanobot/session/keys.py`)

`session_key_for_channel(channel, chat_id, *, unified_session=False)`가 채널/채팅에서 세션 키를 만든다(형식 예: `telegram:123456`). `unified_session=True`면 채널과 무관하게 단일 사용자용 공유 키를 만든다(`agents.defaults.unifiedSession`).

## `Session`

`@dataclass Session`은 한 대화의 메시지와 메타데이터를 담는다. 주요 메서드:

- `add_message(role, content, **kwargs)` — 메시지 추가.
- `get_history(...)` — 컨텍스트 재생용 히스토리 반환. 토큰 예산·규칙에 맞춰 정리하며, `_sanitize_assistant_replay_text`로 재생 텍스트를 위생 처리한다.
- `retain_recent_legal_suffix(...)` — role 교대가 유효한 최근 접미부만 유지(컴팩션 후 정합성).
- `enforce_file_cap(...)` — 디스크 파일 크기 상한 적용.
- `clear()` — 히스토리 비움.

모듈 헬퍼 `replay_max_messages_for_context(context_window_tokens)`는 컨텍스트 창 크기에 따라 재생할 최대 메시지 수를 계산한다(`AgentLoop._replay_token_budget`, `_sync_replay_max_messages`와 연동).

## `SessionManager`

`SessionManager(workspace)`는 `<workspace>/sessions/` 아래 JSONL 파일로 세션을 저장한다.

### 키 인코딩과 경로

- `safe_key(key)` / `_storage_key(key)` / `_decode_storage_key(stem)` — 세션 키를 파일 시스템에 안전한 이름으로 인코딩/디코딩.
- `_get_session_path(key)`, `_get_legacy_session_path`, `_get_legacy_lossy_path` — 현재/구버전 경로 해석(마이그레이션 호환).

### 로드/저장/복구

- `get_or_create(key) -> Session` — 세션을 로드하거나 새로 만든다.
- `_load(key)` — JSONL 파싱. 손상 시 `_repair(key, path=...)`로 복구 시도.
- `save(session, *, fsync=False)` — 원자적 쓰기. `fsync=True`면 durability 보장.
- `flush_all()` — 캐시된 모든 세션 저장.
- `invalidate(key)`, `delete_session(key)` — 캐시 무효화/삭제.

### 포크와 조회

- `fork_session_before_user_index(...)` — 특정 사용자 메시지 이전 지점에서 세션을 복제(WebUI의 fork 기능, [9.2](09.2-backend-webui-apis.md)).
- `read_session_file(key)`, `read_session_metadata(key)` — 원시 파일/메타데이터 읽기.
- `list_sessions() -> list[dict]` — 세션 목록(WebUI 사이드바용).

## 런타임 체크포인트

턴 도중 크래시에서 복구할 수 있도록, 러너는 진행 중 상태를 체크포인트로 남긴다(`AgentRunner._emit_checkpoint` → `AgentRunSpec.checkpoint_callback`, [3.2](03.2-agent-runner-and-llm-provider-interface.md)). `turn_continuation.py`, `history_visibility.py`, `webui_turns.py`, `automation_turns.py`가 세션 계층에서 관련 로직을 담당한다.

## 목표 상태 (`nanobot/session/goal_state.py`)

장기 목표(long-goal)는 세션 메타데이터에 저장된다.

- `sustained_goal_active(metadata)`, `sustained_goal_turn(...)` — 활성 목표 여부/턴.
- `parse_goal_state(blob)`, `goal_state_raw(metadata)` — 목표 상태 파싱.
- `goal_state_runtime_lines(metadata)` — 시스템 프롬프트 런타임 컨텍스트 줄 생성([3.3](03.3-context-builder-and-system-prompts.md)).
- `goal_state_ws_blob(metadata)` — WebUI로 보낼 목표 상태 페이로드([7.4](07.4-websocket-channel-and-webui-protocol.md)).
- `runner_wall_llm_timeout_s(...)` — 목표 실행 벽시계 타임아웃.
