## 정의와 등장 배경

일반 LLM은 대화가 끝나면 아무것도 기억하지 못합니다(stateless). "자기개선"은 이를 넘어:
- **경험 축적**: 지난 대화에서 배운 사실/선호를 장기 저장.
- **능력 확장**: 새 작업 절차를 스스로 문서화해 다음에 재사용.

**왜 필요한가:** 개인 비서 성격의 에이전트는 사용자를 알아갈수록 유용해집니다. 매번 처음부터 시작하면 비서로서
가치가 없습니다. 그래서 "장기 기억"과 "능력의 점진적 축적"이 핵심 설계 목표가 됩니다.

---

## 최신 동향

- **반성/요약(reflection) 루프**: 에이전트가 자신의 행동을 되돌아보고 요약해 메모리에 반영.
- **스킬 라이브러리**: 성공한 절차를 재사용 가능한 단위로 저장(Voyager 등 연구가 대표적).
- **파일 기반 메모리**: 사람이 읽고 편집할 수 있는 메모리(투명성·감사 가능성).

## nanobot에서의 실제 구현

### Dream — 주기적 기억 통합 (`agent/memory.py`)
[08](../08_memory_and_dream.md)에서 상세히 다뤘습니다. 요점:
- `history.jsonl`에 append된 경험을 커서(`.dream_cursor`)로 추적.
- `build_dream_prompt(max_entries=20)`(L531-557): 미처리 기록 + **현재 메모리 파일 실제 내용**을 프롬프트로 구성.
  현재 파일을 임베드하는 이유(docstring L536-539)는 모델이 실제 파일을 근거로 편집해 환각을 줄이기 위함.
- `build_dream_tools()`(L592-): 파일 편집 도구만 주는 **제한된 레지스트리**(최소 권한).
- `dream_content_diff()`(L581-590): 실제 git diff로 변경을 확인해, **자기 보고가 아니라 실제 변경**일 때만 커서 전진.
- 스케줄: cron `"dream"` 작업으로 주기 실행(`cli/commands.py` L1437-). → [11](../11_cron_and_triggers.md).

### Skills — 능력의 점진적 확장 (`agent/skills.py`, `nanobot/skills/`)
[08](../08_memory_and_dream.md) 참고. 요점:
- 스킬은 코드가 아니라 `SKILL.md` 마크다운(`SkillsLoader` docstring L25).
- `build_skills_summary()`(L111-)로 **요약만** 컨텍스트에 넣고 필요 시 본문을 읽는 점진적 로딩.
- 내장 스킬 중 `skill-creator`가 있어 **에이전트가 새 스킬을 스스로 만들** 수 있습니다(`nanobot/skills/skill-creator/`).
- 워크스페이스 스킬이 내장 스킬을 오버라이드해 사용자/에이전트가 능력을 커스터마이즈.

**정리:** nanobot의 자기개선은 "Dream(경험→장기 기억 갱신)"과 "Skills(능력→문서로 축적/확장)"의 결합입니다.
둘 다 사람이 읽고 편집할 수 있는 파일 기반이라 투명하고 감사 가능하며, 실제 파일 변경을 근거로만 상태를 전진시키는
보수적 설계로 환각을 억제합니다.
