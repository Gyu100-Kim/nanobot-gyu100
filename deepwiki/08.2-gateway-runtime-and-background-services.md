# 8.2 Gateway Runtime and Background Services (게이트웨이 런타임과 백그라운드 서비스)

`nanobot gateway`는 nanobot의 장기 실행 런타임이다. 채널을 연결하고, 백그라운드 자동화(Dream, heartbeat, cron)를 돌리며, WebUI/API를 서빙한다. 게이트웨이 명령과 OS 서비스 관리는 `nanobot/cli/gateway.py`에 있다.

## 게이트웨이 설정

`GatewayConfig`(`nanobot/config/schema.py`):

- `host`(기본 `127.0.0.1`), `port`(기본 `18790`) — health/제어 엔드포인트.
- `restartMode`(`auto|exec|spawn|exit`) — 재시작 전략.
- `heartbeat`(`HeartbeatConfig`) — heartbeat 서비스.

health 엔드포인트는 `http://127.0.0.1:18790/health`다(WebSocket/WebUI의 `8765`, API의 `8900`과 구분).

## 서비스 관리 명령 (`nanobot/cli/gateway.py`)

`gateway_app` 서브명령:

| 명령 | 함수 | 역할 |
|---|---|---|
| `gateway status` | `gateway_status` | 실행 상태 |
| `gateway logs` | `gateway_logs` | 로그 조회 |
| `gateway stop` | `gateway_stop` | 정지 |
| `gateway restart` | `gateway_restart` | 재시작 |
| `gateway install-service` | `gateway_install_service` | OS 서비스 등록(systemd/launchd) |
| `gateway uninstall-service` | `gateway_uninstall_service` | 서비스 해제 |

이로써 게이트웨이를 systemd(Linux)나 LaunchAgent(macOS)로 상시 실행할 수 있다([13.1](13.1-docker-and-container-deployment.md)).

## Cron 서비스 (`nanobot/cron/service.py`)

`CronService`는 예약된 에이전트 작업을 관리하는 핵심 백그라운드 서비스다.

### 저장과 동시성

- 잡은 `<workspace>/cron/jobs.json`에 영속화된다(`CronStore`, `nanobot/cron/types.py`).
- `filelock.FileLock`으로 다중 프로세스 동시 접근을 안전하게 처리.
- 타입: `CronJob`, `CronSchedule`, `CronPayload`, `CronJobState`, `CronRunRecord`.

### 스케줄 종류

`_compute_next_run(schedule, now_ms)`가 다음 실행 시각을 계산한다.

- `at` — 특정 시각 1회.
- `every` — 고정 간격 반복.
- (cron 표현식) — croniter 기반 반복.

### 실행

- 타이머가 만료되면 잡 콜백이 자동화 턴을 에이전트 루프에 제출한다(`AgentLoop.submit_cron_turn`). 세션이 바쁘면 지연 큐로 미룬다(`pending_cron_job_ids_for_session`, `_publish_next_deferred_automation_turn`, [3.1](03.1-agent-loop-and-turn-state-machine.md)).
- 각 실행은 run record로 기록된다(`write_automation_run_record`, `safe_run_record_name`).
- `CronJobSkippedError` — 콜백이 의도적으로 건너뛴 경우.

### 시스템 잡

게이트웨이 시작 시 두 보호된 시스템 잡이 등록될 수 있다.

- `dream` — `agents.defaults.dream.enabled`가 true일 때. Dream 통합을 주기 실행([4.2](04.2-memory-store-and-dream-system.md)).
- `heartbeat` — `gateway.heartbeat.enabled`가 true일 때. `<workspace>/HEARTBEAT.md`의 `## Active Tasks`를 읽어 유용한 결과만 최근 활성 채팅으로 보낸다(`HeartbeatConfig.intervalS`, `keepRecentMessages`).

사용자 리마인더/cron 도구 작업은 같은 서비스를 쓰되 보호된 시스템 잡과 구분된다([6.3](06.3-cron-image-generation-and-other-tools.md)).

## 로컬 트리거

로컬 트리거(`/trigger <name>`)는 세션에 바인딩된 자동화다. `nanobot trigger <id> "<message>"`로 외부에서 발화하며, `AgentLoop.submit_local_trigger_turn`으로 처리된다. cron과 마찬가지로 지연 큐를 지원한다(`pending_local_trigger_ids_for_session`).
