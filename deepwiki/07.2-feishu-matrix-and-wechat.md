# 7.2 Feishu, Matrix, and WeChat (Feishu·Matrix·WeChat)

이 문서는 아시아권에서 널리 쓰이는 채널과 Matrix를 다룬다. 모두 `BaseChannel`을 상속하며, 공통 인바운드/아웃바운드 흐름은 [7. Channels](07-channels.md)와 같다.

## Feishu / Lark (`nanobot/channels/feishu.py`)

`FeishuChannel(BaseChannel)`은 Feishu(국제판 Lark) 봇으로 동작한다.

- 인증: app id/secret 기반 자격증명과 이벤트 구독(webhook/이벤트 콜백).
- 인바운드: 텍스트·이미지·파일 메시지를 `InboundMessage`로 변환. 그룹/DM 구분.
- 아웃바운드: Feishu 메시지 카드/텍스트로 전송.
- 서명 검증: 수신 이벤트의 서명/토큰 검증으로 위조 요청 차단.

## Matrix (`nanobot/channels/matrix.py`)

`MatrixChannel(BaseChannel)`은 Matrix 프로토콜(홈서버 + room)로 동작한다.

- 인증: homeserver URL, 사용자/액세스 토큰.
- 인바운드: room 이벤트(m.room.message)를 `InboundMessage`로. E2E 암호화 방 지원 여부는 클라이언트 라이브러리에 의존.
- 아웃바운드: room으로 메시지 전송(Markdown/HTML 포맷).
- 세션: room id를 chat_id로 사용해 방별 세션을 분리.

## WeChat (`nanobot/channels/weixin.py`)

`weixin.py`는 개인/공식 계정 WeChat 연동을 담당한다. 기업용 WeCom은 별도 파일(`wecom.py`)이다([7.3](07.3-slack-whatsapp-and-other.md)).

- 인증: 플랫폼별 자격증명(appid/secret, 토큰).
- 인바운드: WeChat 메시지 XML/이벤트를 `InboundMessage`로 파싱.
- 아웃바운드: 텍스트/미디어 응답 전송. 플랫폼의 응답 시간·형식 제약을 준수.
- 서명 검증: WeChat 서버 서명 검증.

## 공통 고려사항

- **서명/토큰 검증**: 이 채널들은 webhook 기반이 많아, 수신 이벤트의 진위를 검증하는 로직이 핵심이다.
- **미디어 변환**: 이미지/음성 첨부는 다운로드 후 컨텍스트에 넣거나 전사한다.
- **세션 키**: 모두 `session_key_for_channel(channel, chat_id)`로 대화별 히스토리를 유지([4.1](04.1-session-manager.md)).
