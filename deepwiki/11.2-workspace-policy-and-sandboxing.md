# 11.2 Workspace Policy and Sandboxing (워크스페이스 정책과 샌드박싱)

파일·셸 도구가 워크스페이스 밖으로 벗어나지 못하게 하는 것은 nanobot 보안의 두 번째 축이다. 두 모듈이 담당한다: 경로 경계 검사(`workspace_policy.py`)와 클라이언트별 접근 스코프(`workspace_access.py`).

## 경로 경계 (`nanobot/security/workspace_policy.py`)

- `WorkspaceBoundaryError(PermissionError)` — 워크스페이스 경계를 벗어난 접근 시 발생.
- `resolve_path(path, workspace=None, *, strict=False) -> Path` — 경로를 해석. `_resolve_logical_path`가 심볼릭 링크/`..`를 정규화해 우회를 막는다.
- `is_path_within(path, root) -> bool` — 경로가 루트 하위인지 확인.
- `is_path_allowed(path, roots)` / `_is_path_exactly_allowed(...)` — 여러 허용 루트에 대한 판정.
- `require_path_within(...)` — 경계 밖이면 `WorkspaceBoundaryError`를 던지는 강제 검사.
- `resolve_allowed_path(...)` — 허용된 루트 안에서 안전하게 해석된 경로 반환.

파일 도구([6.1](06.1-shell-execution-and-filesystem-tools.md))는 이 함수들로 워크스페이스 경계를 강제한다. `tools.restrictToWorkspace`가 이 정책 의도를 켠다([2](02-configuration.md)).

## 접근 스코프 (`nanobot/security/workspace_access.py`)

클라이언트(특히 WebUI/원격)마다 접근 범위와 샌드박스 상태를 다르게 부여한다.

- `WorkspaceScopeError` — 스코프 위반.
- `WorkspaceScope` — 특정 세션/연결의 접근 범위(허용 루트, 접근 모드).
- `WorkspaceSandboxStatus` — 샌드박스 활성 여부/모드 스냅샷.
- `ToolWorkspace` — 도구에 주입되는 워크스페이스 뷰(허용 경로 집합).
- `WorkspaceScopeResolver` — 요청 컨텍스트로부터 스코프를 해석/생성/바인딩. `WORKSPACE_SCOPE_METADATA_KEY`로 세션 메타데이터에 스코프를 저장.
- 접근 모드/프로바이더 정규화 헬퍼로 로컬(Full Access)과 원격(제한) 클라이언트를 구분한다([7.4](07.4-websocket-channel-and-webui-protocol.md), [9.2](09.2-backend-webui-apis.md)).

## 셸 샌드박싱

셸 실행은 플랫폼별 샌드박스 백엔드로 감싼다(`nanobot/agent/tools/sandbox.py`).

- `workspace_sandbox_status(restrict_to_workspace, workspace)` — 워크스페이스 제한과 가용 백엔드로 샌드박스 상태를 계산.
- 서브에이전트는 이 상태를 격리된 도구 컨텍스트에 주입받는다(`SubagentManager._build_tools`, [3.4](03.4-sub-agents-and-parallel-execution.md)).

## 러너 통합

워크스페이스 위반도 러너가 부드럽게 처리해 모델에 안전한 오류로 전달한다(`AgentRunner._is_workspace_violation`, [3.2](03.2-agent-runner-and-llm-provider-interface.md)).
