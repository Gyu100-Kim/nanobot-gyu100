# 11.1 Network Security and SSRF Guard (네트워크 보안과 SSRF 가드)

`nanobot/security/network.py`는 웹·MCP 요청이 내부/사설 네트워크를 공격(SSRF, Server-Side Request Forgery)하지 못하게 막는다. 웹 도구([6.2](06.2-web-search-and-mcp-tools.md))와 HTTP MCP가 모든 요청을 이 가드로 통과시킨다.

## 화이트리스트

- `configure_ssrf_whitelist(cidrs)` — 차단에서 제외할 CIDR 목록을 설정. 설정 로딩 시 `tools.ssrfWhitelist`가 `nanobot/config/loader.py`의 `_apply_ssrf_whitelist`를 통해 여기로 반영된다([2.1](02.1-config-schema-and-loader.md)). 예: Tailscale용 `100.64.0.0/10`.

## 대상 검증

- `resolve_url_target(url, *, allow_loopback=False) -> (ok, reason, resolved_ips)` — URL의 호스트를 DNS 해석해, 해석된 모든 IP가 안전한지 검사. 반환에 해석된 IP 튜플이 포함된다.
- `validate_url_target(url, *, allow_loopback=False) -> (ok, reason)` — 위의 불리언 래퍼.
- `_is_private(addr)` — private/loopback/link-local/reserved 주소 판별.
- `_normalize_addr(...)` — 주소 정규화(IPv4-mapped IPv6 등).
- `contains_internal_url(command, *, allow_loopback=False)` — 셸 명령 문자열에 내부 URL이 있는지 검사.
- `_is_allowed_loopback_target(...)` — 허용된 loopback 대상(예: WebUI 로컬 서비스 접근, [9.2](09.2-backend-webui-apis.md)) 판별.

## DNS 핀닝

DNS rebinding(해석 후 재해석으로 우회) 공격을 막기 위해, 검증에 쓴 IP를 실제 연결에 고정한다.

- `pin_resolved_url_dns(url, resolved_ips)` — 컨텍스트 안에서 `getaddrinfo`를 검증된 IP로 고정(`_getaddrinfo` 몽키패치).
- `PinnedDNSAsyncTransport(httpx.AsyncBaseTransport)` — 핀닝된 DNS로 요청을 보내는 httpx transport.
- `validate_resolved_url(url)` — 최종 연결 직전 재검증. 리다이렉트마다 호출되어 매 홉의 대상 IP를 다시 확인한다.
- `UnsafeURLRequestError(httpx.RequestError)` — 안전하지 않은 대상일 때 발생.

## 프록시 처리

- `env_proxy_applies_to_url(url)`, `httpx_env_proxy_mounts()`, `_no_proxy_mount_pattern(hostname)` — 환경 프록시(`HTTP_PROXY`/`NO_PROXY`)를 존중하면서도 SSRF 검증과 일관되게 마운트를 구성.

## 러너 통합

도구 실행 중 SSRF 위반이 감지되면 러너가 이를 부드러운 오류로 변환해 모델에 전달한다(`AgentRunner._is_ssrf_violation`, `_ssrf_soft_payload`, [3.2](03.2-agent-runner-and-llm-provider-interface.md)). 프로세스는 중단되지 않고, 에이전트가 대안을 시도할 수 있다.
