# 5.1 OpenAI-Compatible Provider (OpenAI 호환 프로바이더)

`nanobot/providers/openai_compat_provider.py`의 `OpenAICompatProvider(LLMProvider)`는 대부분의 호스팅·로컬 프로바이더가 사용하는 기본 구현이다. OpenAI `chat/completions` 및 `responses` API 형태를 모두 지원한다.

## 생성과 클라이언트

```python
OpenAICompatProvider(...)  # api_key, api_base, spec, extra_headers 등
```

- `_build_client()` / `_ensure_client()` — `openai` SDK 비동기 클라이언트를 준비.
- `_setup_env(api_key, api_base)` — 필요한 환경 변수를 설정.
- `_request_model_name(model_name)` — 게이트웨이 전송 전 모델명 변환(`ProviderSpec.strip_model_prefix(es)` 적용).

## 요청 빌드

- `_build_kwargs(...)` — chat/completions 요청 인자를 구성. temperature 지원 여부(`_supports_temperature`), `max_tokens` vs `max_completion_tokens`(`_requires_max_completion_tokens`) 등을 모델별로 판단.
- `_sanitize_messages(messages)` — 메시지 위생 처리(빈 content, tool_call_id 정규화 `_normalize_tool_call_id` 등).
- `_apply_cache_control(...)` — 프롬프트 캐싱 마커 적용(`supports_prompt_caching` 프로바이더).

## thinking / reasoning 제어

프로바이더마다 추론 토글 주입 방식이 달라, 이를 정규화한다.

- `_model_thinking_style(model_name)`, `_thinking_styles_for(spec, model_name)` — 스타일 결정.
- `_thinking_extra_body(style, thinking_enabled)` — `thinking_type`(DeepSeek/VolcEngine/BytePlus), `enable_thinking`(DashScope), `reasoning_split`(MiniMax) 등을 `extra_body`로 변환.
- `_gateway_reasoning_extra_body(style, effort)` — 게이트웨이 네이티브 reasoning(OpenRouter의 `reasoning.effort`).

`ProviderSpec`의 `thinking_style`, `gateway_reasoning_style`, `reasoning_effort_remap`, `implicit_reasoning_models` 등이 이 로직을 구동한다([2.2](02.2-providers-and-model-presets.md)).

## Responses API 지원

일부 OpenAI 모델은 `responses` API를 쓴다.

- `_should_use_responses_api(...)` — `api_type` 설정과 모델을 보고 responses API 사용 여부 판단.
- `_build_responses_body(...)`, `_merge_responses_extra_body(...)` — responses 요청 본문 구성.
- 서킷 브레이커: `_responses_circuit_key`, `_responses_circuit_allows_probe`, `_record_responses_failure`, `_record_responses_success`, `_should_fallback_from_responses_error` — responses API가 반복 실패하면 chat/completions로 폴백.
- 실제 responses 구현은 `nanobot/providers/openai_responses/` 서브패키지.

## 텍스트 도구 호출 파싱

네이티브 도구 호출을 지원하지 않는 모델을 위해, 응답 텍스트에서 도구 호출을 추출한다.

- `_extract_text_tool_calls(content)` — 텍스트/JSON 펜스(`_strip_json_fence`)에서 `ToolCallRequest`를 파싱.
- `_short_tool_id()` — 도구 호출 ID 생성.

## 로컬·게이트웨이 감지

- `_is_local_endpoint(...)`, `_is_direct_openai_base(...)` — 로컬(vLLM/Ollama/LM Studio)·직접 OpenAI 엔드포인트 감지.
- `_uses_openrouter_attribution(...)` — OpenRouter 어트리뷰션 헤더 적용.

## 타임아웃

- `_openai_compat_timeout_s()`, `_float_env(name, default)` — 환경 변수 기반 타임아웃.
- 스트리밍 유휴 타임아웃은 베이스의 `resolve_stream_idle_timeout_s`(`base.py`)로 계산.
