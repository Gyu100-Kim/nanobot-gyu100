# 13.1 Docker and Container Deployment (Docker와 컨테이너 배포)

nanobot은 멀티스테이지 `Dockerfile`과 `docker-compose.yml`을 제공한다.

## Dockerfile (멀티스테이지)

### 1단계: WebUI 빌드

```dockerfile
FROM node:24-bookworm-slim AS webui-builder
WORKDIR /app/webui
RUN npm ci
COPY webui/ ./
RUN mkdir -p /app/nanobot/web && npm run build
```

WebUI를 먼저 빌드해 `/app/nanobot/web/dist`에 산출물을 만든다([9.1](09.1-frontend-components-and-state.md)).

### 2단계: 파이썬 이미지

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim
```

- `uv` 기반 파이썬 3.12 이미지.
- 시스템 패키지: `ca-certificates git bubblewrap openssh-client libmagic1`. 여기서 **bubblewrap**은 셸 샌드박싱에 쓰인다([11.2](11.2-workspace-policy-and-sandboxing.md)), `libmagic1`은 파일 타입 감지에 쓰인다.
- 의존성 캐싱을 위해 `pyproject.toml` 등 메타데이터를 먼저 복사해 `uv pip install --system ".[whatsapp]"`로 설치(`NANOBOT_SKIP_WEBUI_BUILD=1`로 WebUI 재빌드 생략, 1단계 산출물 재사용).
- 소스와 1단계의 `nanobot/web/dist/`를 복사한 뒤 재설치.
- 비루트 사용자 `nanobot`(uid 1000)로 실행, `HOME=/home/nanobot`.

### 실행 규약

```dockerfile
EXPOSE 18790 8765
ENTRYPOINT ["entrypoint.sh"]
CMD ["status"]
```

- 노출 포트: `18790`(게이트웨이 health), `8765`(WebUI/WebSocket).
- 진입점은 `entrypoint.sh`이고 기본 커맨드는 `status`. 게이트웨이로 띄우려면 `docker run ... gateway` 처럼 커맨드를 덮어쓴다.

## docker-compose

`docker-compose.yml`은 컨테이너와 볼륨을 정의한다. 워크스페이스/설정을 볼륨으로 영속화하고 포트를 매핑한다. API 키 등은 환경 변수로 주입해 `${ENV}` 치환과 연동한다([2.1](02.1-config-schema-and-loader.md)).

## systemd / LaunchAgent

컨테이너 대신 OS 서비스로 운영하려면 게이트웨이 서비스 설치 명령을 쓴다([8.2](08.2-gateway-runtime-and-background-services.md)).

```bash
nanobot gateway install-service    # systemd(Linux) / LaunchAgent(macOS)
nanobot gateway status
nanobot gateway uninstall-service
```

## 운영 체크리스트

1. 워크스페이스·설정 볼륨 영속화.
2. 프로바이더 자격증명을 환경 변수로 주입.
3. 원격 노출 시 TLS + 토큰 인증([7.4](07.4-websocket-channel-and-webui-protocol.md), [10.1](10.1-api-endpoints-and-authentication.md)).
4. 셸 도구를 쓰면 bubblewrap 등 샌드박스 백엔드가 이미지에 포함됐는지 확인.
