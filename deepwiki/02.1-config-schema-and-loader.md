# 2.1 Config Schema and Loader (설정 스키마와 로더)

## 스키마 (`nanobot/config/schema.py`)

설정은 Pydantic v2 모델로 정의된다. 공통 베이스 클래스 `Base`는 camelCase 별칭 생성과 `populate_by_name`을 설정해, JSON은 camelCase로 쓰되 파이썬 코드는 snake_case 속성으로 접근할 수 있게 한다.

루트는 `Config(BaseSettings)`다. 주요 특징:

- `Config.__init__`은 `type(self).__pydantic_complete__`가 아직 완성되지 않았으면 `_resolve_tool_config_refs()`를 호출해 도구별 하위 설정 타입 참조를 지연 해석한다. 이는 도구 설정 클래스(`WebToolsConfig`, `ExecToolConfig` 등)를 각 도구 구현 옆에 둘 수 있게 하려는 설계다(`ToolsConfig`의 `_lazy_default` 참조).
- `@model_validator(mode="after") _validate_model_preset`은 다음을 강제한다.
  - `"default"`는 `agents.defaults` 전용 예약어라 `modelPresets` 키로 쓸 수 없다.
  - `agents.defaults.modelPreset`이 지정되면 반드시 `modelPresets`에 존재해야 한다.
  - 문자열 `fallbackModels` 엔트리도 `modelPresets`에 있어야 한다.

### 모델 프리셋 해석

- `ModelPresetConfig`: `label`, `model`, `provider`(기본 `"auto"`), `maxTokens`(8192), `contextWindowTokens`(200000), `temperature`(0.1), `reasoningEffort`. `to_generation_settings()`는 `GenerationSettings`로 변환한다.
- `Config.resolve_default_preset()`: `agents.defaults` 필드로부터 암묵적 `default` 프리셋을 만든다.
- `Config.resolve_preset(name)`: 이름 있는 프리셋 또는 암묵적 default를 반환. 없으면 `KeyError`.

### 프로바이더 매칭

- `ProvidersConfig`는 `model_config = ConfigDict(extra="allow")`로 임의 커스텀 프로바이더를 허용한다. `convert_extra_providers` 검증기는 커스텀 키가 내장 프로바이더 이름(`registry.find_by_name`)과 충돌하면 오류를 낸다.
- `Config._match_provider(model, preset)`은 registry(`PROVIDERS`)와 API 키/base URL 힌트로 `(ProviderConfig, spec_name)`을 해석한다.
- 부수 헬퍼: `get_provider`, `get_provider_name`, `get_api_key`, `get_api_base`.

### 검증 예시

- `ApiConfig.wildcard_host_requires_auth`: `host`가 `0.0.0.0`/`::`인데 `apiKey`가 비면 `ValueError`.
- `ProviderConfig._validate_thinking_style`: `thinkingStyle`은 `thinking_type`, `enable_thinking`, `reasoning_split` 중 하나이거나 비어 있어야 한다.

## 로더 (`nanobot/config/loader.py`)

- `load_config(config_path)`: 파일을 읽어 `Config`로 파싱한다. 내부에서 `_migrate_config`로 구버전 스키마를 마이그레이션하고, `resolve_config_env_vars`로 `${ENV}` 치환, `_apply_ssrf_whitelist`로 SSRF 화이트리스트를 네트워크 모듈에 반영한다.
- `save_config(config, config_path)`: `Config`를 camelCase 별칭 JSON으로 직렬화해 디스크에 쓴다.
- `set_config_path` / `get_config_path`: 전역 활성 설정 경로 관리.
- `resolve_config_env_vars` → `_resolve_in_place` → `_resolve_env_vars` → `_env_replace`: `${VAR}` 패턴을 재귀적으로 치환.
- `_migrate_config(data)`: 오래된 키를 현재 스키마로 변환.

## 경로 헬퍼 (`nanobot/config/paths.py`)

| 함수 | 반환 |
|---|---|
| `get_config_path()` | 기본 `~/.nanobot/config.json` |
| `get_data_dir()` | 데이터 루트 |
| `get_runtime_subdir(name)` | 런타임 하위 디렉토리(`webui/`, `media/`, `logs/` 등) |
| `get_media_dir(channel)` | 미디어 저장 경로 |
| `get_cron_dir()`, `get_logs_dir()`, `get_webui_dir()` | 각 런타임 영역 |
| `get_workspace_path(workspace)` | 워크스페이스 경로 |
| `is_default_workspace(...)` | 기본 워크스페이스 여부 |

기본 경로 요약(`docs/architecture.md`):

| 경로 | 기본값 |
|---|---|
| Config | `~/.nanobot/config.json` |
| Workspace | `~/.nanobot/workspace/` |
| Sessions | `<workspace>/sessions/*.jsonl` |
| Memory | `<workspace>/memory/` |
| Cron store | `<workspace>/cron/jobs.json` |
