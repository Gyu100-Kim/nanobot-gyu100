# 배경지식 03. 자기개선 에이전트 — Dream + Skills

> **이 문서에서 다루는 큰 맥락**
>
> "자기개선 에이전트"는 경험을 통해 스스로 지식/능력을 갱신하는 에이전트입니다. nanobot에서는 두 축으로
> 나타납니다: (1) **Dream[(용어사전)](../../dict/03_memory_context_session.md#dream)** — 대화 기록을 주기적으로 요약해 장기 메모리를 스스로 갱신, (2) **Skills** —
> 새 절차/능력을 마크다운으로 추가(자기 확장). 이 문서는 그 배경이 되는 하위 개념들(무상태성, 장기 기억,
> 반성 루프, 스킬 라이브러리, 검증 게이트)과 근간 논문(Generative Agents, Reflexion, Voyager[(용어사전)](../../dict/08_ai_llm_concepts.md#voyager) 등),
> 그리고 `agent/memory.py`, `agent/skills.py`, `nanobot/skills/`로의 연결을 다룹니다.

## 비유로 먼저 이해하기 — 스스로 공부하는 수련생

보통의 프로그램은 만들어진 날의 실력 그대로입니다. "자기개선 에이전트"는 **일하면서 배우는
수련생**을 목표로 합니다. 배움의 재료는 자신의 경험(대화 기록)입니다.

두 개의 축이 있습니다.

- **복습(Dream)** — 수련생이 밤마다 그날의 일지를 읽고 "중요한 교훈"을 자기 노트에 정리하는
  것. nanobot에서는 주기적으로 AI가 `history.jsonl`(일지)을 읽고 `MEMORY.md`(교훈 노트),
  `SOUL.md`(태도), `USER.md`(고객 정보)를 스스로 고쳐 씁니다.
- **비법 노트 쌓기(Skill library)** — 한 번 익힌 작업 요령을 문서(SKILL.md)로 남겨,
  다음에는 처음부터 헤매지 않는 것. 게임 마인크래프트에서 AI가 스스로 기술을 쌓아 간
  Voyager 연구(2023)가 이 아이디어의 대표적 사례입니다.

중요한 주의점 하나: 수련생의 "다 했습니다!"라는 자기 보고를 그대로 믿으면 안 됩니다.
실제로 되는지 **검증 게이트**(테스트 실행 등)를 거쳐야 진짜 배움이 쌓입니다. 또한 nanobot은
기억을 데이터베이스가 아닌 **사람이 읽을 수 있는 파일**로 두어, 무엇을 배웠는지 언제든
열어 보고 고칠 수 있게 했습니다(투명성).

**꼭 가져가야 할 것 3가지**

1. 자기개선 = 경험(로그)을 장기 기억과 스킬 문서로 바꾸는 순환.
2. Dream은 "밤의 복습", Skill은 "쌓여 가는 비법 노트"다.
3. 자기 보고는 검증을 거쳐야 하고, 파일 기반 기억은 투명하게 감사할 수 있다.

## 정의와 핵심 아이디어

일반 LLM은 대화가 끝나면 아무것도 기억하지 못합니다(**stateless** — 무상태). 모델 가중치는 대화로 바뀌지 않으므로,
"기억"과 "성장"은 전적으로 **모델 바깥의 런타임**이 만들어야 합니다. "자기개선"은 이를 넘어:

- **경험 축적**: 지난 대화에서 배운 사실/선호를 장기 저장 → 다음 대화의 컨텍스트로 주입.
- **능력 확장**: 새 작업 절차를 스스로 문서화해 다음에 재사용.

**왜 필요한가:** 개인 비서 성격의 에이전트는 사용자를 알아갈수록 유용해집니다. 매번 처음부터 시작하면 비서로서
가치가 없습니다. 그래서 "장기 기억"과 "능력의 점진적 축적"이 핵심 설계 목표가 됩니다.

주의할 구분: 여기서의 자기개선은 **가중치 업데이트(파인튜닝)가 아니라**, 모델이 읽는 **텍스트 자산(메모리 파일,
스킬 문서)을 갱신**하는 것입니다. "in-context learning을 위한 자료를 스스로 만든다"고 이해하면 정확합니다.

## 하위 개념 상세

### (a) 기억의 계층: working / episodic / semantic
인지과학의 기억 분류를 에이전트에 대응시키면 이해가 쉽습니다.
- **작업 기억(working memory)** = 현재 컨텍스트 창 안의 대화 (→ [02](02_context_compression.md)).
- **일화 기억(episodic memory)** = "무슨 일이 있었는가"의 사건 로그. append-only 이력이 여기 해당.
- **의미 기억(semantic memory)** = 사건에서 추출한 일반화된 사실/선호("사용자는 아침 요약을 원한다").

자기개선의 핵심 과정은 **일화 → 의미로의 증류(distillation)** 입니다. 원시 사건 로그를 그대로 쌓기만 하면
검색도 주입도 어려우므로, 주기적으로 요약·일반화해 의미 기억으로 옮깁니다.

### (b) 반성 루프(reflection loop)
에이전트가 자신의 행동/경험을 되돌아보고 교훈을 추출하는 주기적 과정입니다.
- **Generative Agents**(2023)의 "reflection": 축적된 관찰이 임계치를 넘으면 상위 수준의 통찰을 생성해 메모리에 저장.
- **Reflexion**(2023): 실패 경험을 언어로 반성해 다음 시도의 컨텍스트에 넣으면 성능이 오름 — "언어적 강화학습".

공통 구조: **경험 수집 → (주기/임계치 도달 시) LLM으로 반성/요약 → 결과를 다음 실행의 입력으로.**
사람이 자면서 기억을 정리하는 것에 비유되어 "dream"이라는 이름이 붙곤 합니다.

### (c) 스킬 라이브러리(skill library)
성공한 절차를 재사용 가능한 단위로 저장하는 것. **Voyager**(2023)가 대표적입니다 — 마인크래프트 에이전트가
성공한 행동을 코드(스킬)로 저장하고, 이후 그 스킬들을 조합해 더 복잡한 목표를 달성했습니다.
스킬 표현 방식은 두 갈래입니다:
- **코드 스킬**(Voyager): 실행 가능하지만 작성/검증 비용이 높음.
- **문서 스킬**(절차서/프롬프트): LLM이 읽고 따라 하는 자연어 절차. 작성이 쉽고 비개발자도 만들 수 있음.
  Anthropic의 **Agent Skills[(용어사전)](../../dict/08_ai_llm_concepts.md#agent-skills)**(2025, `SKILL.md` + frontmatter 규격)가 이 방식을 표준화했습니다.

### (d) 점진적 로딩(progressive disclosure)
스킬이 많아지면 전부 컨텍스트에 넣을 수 없습니다. 해법은 "목록(이름+한 줄 설명)만 상시 주입하고,
본문은 필요할 때 파일 읽기 도구로 로드"하는 2단계 구조입니다. 이는 [02](02_context_compression.md)의
컨텍스트 예산 문제에 대한 스킬 측의 대답이기도 합니다.

### (e) 검증 게이트(verification gate) — 자기 보고를 믿지 않기
LLM에게 "메모리를 갱신했니?"라고 물으면 안 했어도 했다고 답할 수 있습니다(환각).
견고한 자기개선 시스템은 **외부에서 검증 가능한 신호**(실제 파일 diff, 테스트 통과 여부)로만 상태를 전진시킵니다.
또한 자기 갱신 작업에는 **최소 권한**(파일 편집 도구만)을 주어, 반성 과정이 다른 부작용을 일으키지 못하게 합니다.

### (f) 파일 기반 메모리 — 투명성과 감사 가능성
메모리를 벡터 DB가 아니라 사람이 읽을 수 있는 마크다운 파일로 두면: (1) 사용자가 직접 열람/수정 가능,
(2) git으로 버전 관리·감사 가능, (3) "에이전트가 나에 대해 뭘 기억하는가"가 투명해집니다.
트레이드오프는 검색력입니다 — 대규모 기억에는 임베딩 검색이 유리하지만, 개인 비서 규모에서는 파일이 충분하며
단순성·투명성의 이득이 큽니다.

## 개념 간 관계

```text
무상태 LLM (기억 없음)
    │ 런타임이 보완
    ▼
일화 기억 (append-only 사건 로그)
    │ 반성 루프 (주기적 증류)          ←— Generative Agents / Reflexion
    ▼
의미 기억 (장기 메모리 파일)  ──→ 매 턴 시스템 프롬프트에 주입 (→ 02, 07 문서)
    │
스킬 라이브러리 (절차의 축적)          ←— Voyager / Agent Skills
    │ 점진적 로딩 (요약만 상시, 본문은 필요 시)
    ▼
자기 확장 (스킬이 스킬을 만듦: skill-creator)
    │ 전체를 관통하는 규율
    └─ 검증 게이트 (실제 diff로만 전진) + 최소 권한 (편집 도구만)
```

- 반성 루프는 [02](02_context_compression.md)의 요약/통합과 메커니즘이 같지만 **목적지가 다릅니다**
  (컨텍스트 절약 vs 장기 지식 축적).
- 스킬 주입은 [01](01_tool_calling_agents.md)의 도구와 상보적입니다 — 도구는 "할 수 있는 것", 스킬은 "하는 방법".

## 최신 동향

- **반성/요약(reflection) 루프**: 에이전트가 자신의 행동을 되돌아보고 요약해 메모리에 반영.
- **스킬 라이브러리**: 성공한 절차를 재사용 가능한 단위로 저장(Voyager, Agent Skills).
- **파일 기반 메모리**: 사람이 읽고 편집할 수 있는 메모리(투명성·감사 가능성) — 개인 에이전트 프레임워크들의 공통 선택.
- **메모리의 자동 큐레이션**: 무엇을 기억하고 무엇을 잊을지(중요도/최신성)의 정책 연구.

## nanobot에서의 실제 구현

### Dream — 주기적 기억 통합 (`agent/memory.py`)
[08](../08_memory_and_dream.md)에서 상세히 다뤘습니다. 위 하위 개념과의 대응:
- `history.jsonl` = **일화 기억**(append-only 사건 로그), `MEMORY.md`/`SOUL.md`/`USER.md` = **의미 기억**.
- Dream cron 작업 = **반성 루프**: `.dream_cursor` 커서로 미처리 기록을 추적하고 주기 실행(`cli/commands.py` L1437-).
- `build_dream_prompt(max_entries=20)`(L531-557): 미처리 기록 + **현재 메모리 파일 실제 내용**을 프롬프트로 구성.
  현재 파일을 임베드하는 이유(docstring L536-539)는 모델이 실제 파일을 근거로 편집해 환각을 줄이기 위함.
- `build_dream_tools()`(L592-): 파일 편집 도구만 주는 **제한된 레지스트리** — 위 (e)의 최소 권한.
- `dream_content_diff()`(L581-590): 실제 git diff로 변경을 확인해, **자기 보고가 아니라 실제 변경**일 때만 커서 전진
  — 위 (e)의 검증 게이트를 그대로 구현한 사례.
- 메모리가 전부 마크다운 파일 + git 커밋(L1490-1496) — 위 (f)의 파일 기반 투명성.

### Skills — 능력의 점진적 확장 (`agent/skills.py`, `nanobot/skills/`)
[08](../08_memory_and_dream.md) 참고. 위 하위 개념과의 대응:
- 스킬은 코드가 아니라 `SKILL.md` 마크다운(`SkillsLoader` docstring L25) — 위 (c)의 **문서 스킬** 방식이며
  Anthropic Agent Skills 규격(frontmatter 메타데이터)과 같은 계열.
- `build_skills_summary()`(L111-)로 **요약만** 컨텍스트에 넣고 필요 시 본문을 읽는 — 위 (d)의 점진적 로딩.
- 내장 스킬 중 `skill-creator`가 있어 **에이전트가 새 스킬을 스스로 만들** 수 있습니다(`nanobot/skills/skill-creator/`)
  — Voyager의 스킬 축적 아이디어의 문서판.
- 워크스페이스 스킬이 내장 스킬을 오버라이드해 사용자/에이전트가 능력을 커스터마이즈.

**정리:** nanobot의 자기개선은 "Dream(일화→의미 기억 증류, Generative Agents/Reflexion 계열)"과
"Skills(절차의 축적, Voyager/Agent Skills 계열)"의 결합입니다. 둘 다 사람이 읽고 편집할 수 있는 파일 기반이라
투명하고 감사 가능하며, 실제 파일 변경(git diff)을 근거로만 상태를 전진시키는 보수적 설계로 환각을 억제합니다.

## 차근차근 정리 — 한 장면으로 복습

에이전트가 한 달 동안 쓰이면서 "스스로 나아지는" 과정을 압축하면:

1. 매일의 대화 요지가 **일기(episodic memory, `history.jsonl`)**에 쌓입니다.
2. 밤마다(Dream) LLM이 일기의 미처리 구간을 읽고, 오래 기억할 가치가 있는 사실만
   **정리 노트(semantic memory, `MEMORY.md`)**로 옮겨 적습니다.
3. 이때 "정리했다"는 말이 아니라 **파일이 실제로 바뀌었는지(diff)**로 성공을 판정하고,
   성공했을 때만 커서를 전진시킵니다 — 자기개선의 신뢰성 장치.
4. 반복되는 작업 요령은 **스킬(SKILL.md)**로 저장됩니다. 다음부터는 배운 요령의 목차가
   컨텍스트에 실려, 같은 일을 더 잘하게 됩니다(Voyager의 스킬 라이브러리와 같은 발상).
5. 이 모든 것이 사람이 열어 읽고 고칠 수 있는 **마크다운 파일**이라는 점이 nanobot의
   설계 철학입니다 — 학습 결과가 블랙박스가 아니라 문서입니다.
