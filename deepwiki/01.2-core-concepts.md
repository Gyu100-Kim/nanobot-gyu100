# 1.2 Core Concepts (핵심 개념)

이 문서는 소스를 읽기 전에 nanobot의 구성 요소를 이해하기 위한 개념 지도다. 상세 소스 소유권은 이후 장을 참고하라.

## Config vs Workspace

기본 인스턴스는 `~/.nanobot/` 아래에 산다(`nanobot/config/paths.py`).

| 경로 | 의미 |
|---|---|
| `~/.nanobot/config.json` | 인스턴스 설정: 프로바이더, 모델 기본값, 채널, 도구, 게이트웨이, API, 런타임 옵션 |
| `~/.nanobot/workspace/` | 에이전트 워크스페이스: 메모리, 세션, heartbeat, cron, 스킬, 산출물 |

`config.json`은 camelCase와 snake_case 키를 모두 받지만, 저장 시에는 camelCase 별칭으로 쓴다(예: `apiKey`, `modelPresets`, `intervalS`). 자세한 내용은 [2. Configuration](02-configuration.md).

## 한 번의 에이전트 턴 (One Agent Turn)

일반적인 턴 흐름(`docs/concepts.md`):

1. 채널이 사용자 메시지를 받아 message bus에 발행한다.
2. 에이전트 루프가 세션 키를 고르고, 워크스페이스·스킬·메모리·최근 메시지·채널 메타데이터·런타임 설정으로 컨텍스트를 만든다.
3. 프로바이더가 모델 요청을 받는다.
4. 모델이 도구를 요청하면 러너가 실행하고 결과를 다시 모델에 넣는다.
5. 최종 답변이 세션에 저장되고 채널로 되돌아간다.

이 흐름은 CLI든 WebUI든 Telegram이든 동일하다.

## Agent Loop vs Agent Runner

이 분리를 이해하는 것이 디버깅의 핵심이다(`docs/architecture.md`).

- `AgentLoop`(`nanobot/agent/loop.py`)는 **채널을 마주하는** 턴을 소유한다: 인바운드 수신, 세션/워크스페이스 스코프 결정, 컨텍스트 빌드, 훅·진행 상황·채널 메타데이터 배선, 아웃바운드 발행.
- `AgentRunner`(`nanobot/agent/runner.py`)는 **모델을 마주하는** 루프를 소유한다: 프로바이더 호출, 스트리밍 델타·추론 블록 처리, 도구 실행, 결과 재투입, 최종 답 생성 또는 런타임 한계 도달 시 종료.

채널 라우팅·세션 키·워크스페이스 선택·아웃바운드 문제는 `loop.py`에서, 프로바이더 호출·도구 호출·스트리밍·반복 한계 문제는 `runner.py`에서 시작하라.

## Provider와 Model 선택

활성 모델은 보통 이름 붙은 `modelPresets` 엔트리에서 온다(`agents.defaults.modelPreset`로 선택). 프로바이더 해석 순서(`nanobot/config/schema.py`의 `Config._match_provider`, `docs/concepts.md`):

1. 활성 프리셋의 provider가 `"auto"`가 아니면 그것을 사용.
2. `"auto"`면 모델 이름, 설정된 API 키, 로컬 base URL, 게이트웨이 프로바이더로 추론.
3. OpenAI Codex, GitHub Copilot 같은 OAuth 프로바이더는 명시적 로그인과 명시적 provider/model 선택이 필요하다.

## Channels와 Sessions

각 채널은 인바운드 메시지를 세션 키에 매핑한다(`nanobot/session/keys.py`의 `session_key_for_channel`, 형식 예 `channel:id`). 이로써 독립 대화가 별도 히스토리를 유지한다. `agents.defaults.unifiedSession`을 켜면 한 세션을 채널 간 공유해 단일 사용자 멀티 디바이스 시나리오를 지원한다.

## Memory, Sessions, Dream

두 개의 관련 저장소가 있다.

| 저장소 | 위치 | 목적 |
|---|---|---|
| Sessions | `<workspace>/sessions/*.jsonl` | 최근 대화 턴을 컨텍스트로 재생 |
| Memory | `<workspace>/memory/MEMORY.md`, `history.jsonl` | 장기 사실과 압축된 히스토리 |

Dream은 주기적 통합(consolidation) 잡으로, 누적 히스토리를 읽어 워크스페이스 메모리를 갱신한다. 자세한 내용은 [4. Memory and Session Management](04-memory-and-session-management.md).

## Tools와 안전성

도구는 내장 모듈과 플러그인 엔트리포인트에서 자동 발견된다(`nanobot/agent/tools/loader.py`, `registry.py`). 파일 읽기/쓰기/편집, shell 실행(샌드박스), web 검색/조회(SSRF 검사), MCP 서버, cron/트리거/heartbeat, 이미지 생성, subagent/self-inspection 등이 있다. 보안 통제는 [11. Security](11-security.md) 참고.

## Background Jobs

`nanobot gateway`가 시작되면 워크스페이스 스코프 자동화(automation)를 실행하고 시스템 잡을 등록한다.

- `dream`: `agents.defaults.dream.enabled`가 true일 때.
- `heartbeat`: `gateway.heartbeat.enabled`가 true일 때. `<workspace>/HEARTBEAT.md`의 `## Active Tasks`를 읽어 유용한 결과만 최근 활성 채팅으로 보낸다.

사용자 리마인더는 같은 cron 서비스를 쓰지만 보호된 heartbeat 시스템 잡과는 다르다. 로컬 트리거(`/trigger <name>`)는 세션에 묶이며 `nanobot trigger <id> "<message>"`로 외부에서 호출한다.
