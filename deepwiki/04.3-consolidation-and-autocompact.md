# 4.3 Consolidation and AutoCompact (컨솔리데이션과 자동 컴팩션)

세션이 무한히 커지지 않도록 nanobot은 두 가지 압축 흐름을 쓴다: 토큰 예산이 압박될 때 도는 **Consolidator**와, 유휴 세션을 아카이브하는 **AutoCompact**.

## Consolidator (`nanobot/agent/memory.py`)

`Consolidator`는 컨텍스트 창을 압박하는 오래된 메시지를 요약해 `history.jsonl`에 넣는 경량 통합기다.

```python
Consolidator(store, provider, model, sessions, context_window_tokens,
             build_messages, get_tool_definitions,
             max_completion_tokens=4096, consolidation_ratio=0.5,
             unified_session=False)
```

- `context_window_tokens`와 `consolidation_ratio`(설정 `agents.defaults.consolidationRatio`, 기본 0.5)로 목표 유지 크기를 정한다. 0.5면 압축 후 예산의 50%를 유지.
- 상수: `_MAX_CONSOLIDATION_ROUNDS = 5`(최대 라운드), `_SAFETY_BUFFER = 1024`(토큰 추정 오차 여유).
- 페이로드 상한: `_ARCHIVE_SUMMARY_MAX_CHARS`(LLM 요약 8000), `_RAW_ARCHIVE_MAX_CHARS`(LLM 실패 시 원시 덤프 16000), `_HISTORY_ENTRY_HARD_CAP`(비상 상한 64000).

동작: 컨텍스트가 예산을 넘으면 가장 오래된 안전한 구간을 LLM으로 요약(템플릿 `nanobot/templates/agent/consolidator_archive.md`)해 `history.jsonl`에 append하고, 세션에서는 해당 구간을 요약으로 치환한다. LLM 호출이 실패하면 원시 텍스트를 잘라 아카이브(fallback)한다. Consolidator는 `AgentLoop`의 COMPACT 상태(`_state_compact`)에서 호출된다([3.1](03.1-agent-loop-and-turn-state-machine.md)).

토큰 추정은 `tiktoken` 기반 헬퍼(`nanobot/utils/helpers.py`)를 사용한다.

## AutoCompact (`nanobot/agent/autocompact.py`)

`AutoCompact`는 유휴 세션의 히스토리를 배경에서 아카이브해, 다음에 그 세션이 활성화될 때 컨텍스트가 가볍게 시작하도록 한다.

```python
AutoCompact(sessions: SessionManager, consolidator: Consolidator, ...)
```

주요 메서드:

- `check_expired(schedule_background, ...)` — TTL이 지난 세션을 찾아 백그라운드 아카이브를 스케줄. TTL은 `agents.defaults.sessionTtlMinutes`(별칭 `idleCompactAfterMinutes`, 기본 15분, 0이면 비활성).
- `_is_expired(ts, ...)` — 마지막 활동 시각으로 만료 판정.
- `_has_compactable_idle_tail(key)` — 압축 가능한 유휴 꼬리가 있는지 확인.
- `_archive(key)` — 실제 아카이브 수행(Consolidator 활용).
- `prepare_session(session, key)` — 세션 준비 시 요약 프리픽스를 적용, `(session, summary)` 반환.
- `_format_summary(text, last_active)` — 아카이브 요약 문자열 포맷.
- `_is_internal_session(key)` — Dream 등 내부 세션 제외.

## 두 흐름의 구분

| 항목 | Consolidator | AutoCompact |
|---|---|---|
| 트리거 | 컨텍스트 창 압박(턴 도중) | 세션 유휴 TTL 경과(배경) |
| 목적 | 활성 대화를 예산 안에 유지 | 유휴 세션을 미리 정리 |
| 저장 | `history.jsonl` 요약 | 세션 요약 프리픽스 + 아카이브 |

두 흐름 모두 최종적으로는 `history.jsonl`을 채워, 이후 Dream이 장기 지식으로 승격시킬 재료가 된다([4.2](04.2-memory-store-and-dream-system.md)).
