# 4.2 Memory Store and Dream System (메모리 스토어와 Dream 시스템)

장기 메모리는 `nanobot/agent/memory.py`의 `MemoryStore`가 관리한다. 이 클래스는 워크스페이스의 지식 파일과 히스토리 아카이브를 다루고, Dream 통합 잡을 위한 프롬프트/도구를 만든다.

## 지식 파일

`MemoryStore(workspace, max_history_entries=...)`는 다음 파일을 읽고 쓴다.

| 파일 | 역할 | 접근자 |
|---|---|---|
| `SOUL.md` | 봇의 장기 목소리·커뮤니케이션 스타일 | `read_soul` / `write_soul` |
| `USER.md` | 사용자에 대한 안정적 지식 | `read_user` / `write_user` |
| `memory/MEMORY.md` | 프로젝트 사실·결정·지속 컨텍스트 | `read_memory` / `write_memory` |
| `memory/history.jsonl` | append-only 히스토리 요약 | `append_history`, `read_unprocessed_history` |

`get_memory_context()`는 위 파일들을 합쳐 시스템 프롬프트에 넣을 메모리 컨텍스트를 만든다([3.3](03.3-context-builder-and-system-prompts.md)). `git`(→ `GitStore`, `nanobot/utils/gitstore.py`)로 장기 파일 변경을 버전 관리한다.

## 히스토리 아카이브

`history.jsonl`은 cursor 기반 append-only 파일이다. 각 줄은 JSON 객체다.

```json
{"cursor": 42, "timestamp": "2026-04-03 00:02", "content": "- User prefers dark mode\n- Decided to use PostgreSQL"}
```

- `append_history(...)` — 새 요약 추가.
- cursor 관리: `_read_cursor_counter`, `_next_cursor`, `get_latest_cursor`.
- `read_unprocessed_history(since_cursor)` — 특정 cursor 이후 미처리 항목.
- `read_recent_history_for_prompt(...)` — 프롬프트용 최근 항목.
- `compact_history()` — 아카이브 압축.
- 구버전 `HISTORY.md` 마이그레이션: `_maybe_migrate_legacy_history`, `_parse_legacy_history`, `_split_legacy_history_chunks` 등.

`_is_internal_history_session(session_key)`는 내부 세션(예: Dream 자체)이 아카이브에 오염을 남기지 않게 필터링한다.

## Dream 시스템

Dream은 느리고 사려 깊은 통합 계층으로, `history.jsonl`의 새 항목을 읽어 `SOUL/USER/MEMORY`를 최소 변경으로 수정한다.

### Dream cursor

- `get_last_dream_cursor()` / `set_last_dream_cursor(cursor)` — Dream이 어디까지 소비했는지 추적(`memory/.dream_cursor`). Consolidator의 write cursor(`memory/.cursor`)와 구분된다.

### Dream 프롬프트/도구

- `build_dream_prompt(*, max_entries=20) -> (prompt, cursor) | None` — 미처리 히스토리, 현재 메모리 파일(`_render_current_memory_files`), Dream 템플릿(`_dream_template`, 기본 `default_dream_prompt`)을 합쳐 프롬프트를 만든다. 워크스페이스별 오버라이드는 `dream_prompt_file()`(`prompts/dream.md`)와 `has_dream_prompt_override()`로 지원한다.
- `build_dream_tools()` — Dream 실행이 사용할 도구 세트(메모리 파일 편집).
- `dream_run_completed(resp)` — 실행 완료 판정.
- `dream_content_diff()` — 변경 diff 계산(`/dream-log`용).
- `dream_session_key()` — Dream 전용 내부 세션 키.
- `raw_archive(...)` — 원시 아카이브 접근.

### 스케줄과 설정

Dream은 `agents.defaults.dream`(`DreamConfig`, `nanobot/config/schema.py`)로 설정된다.

- `intervalH` — 실행 주기(시간). 내부적으로 `every` 스케줄.
- `cron` — 정밀 cron 표현식 오버라이드(`build_schedule`, `describe_schedule`).
- `modelOverride` — (예약, 현재 미구현) Dream 전용 모델.
- `enabled` — 게이트웨이 시작 시 `dream` 시스템 잡 등록 여부([8.2](08.2-gateway-runtime-and-background-services.md)).

`maxBatchSize`, `maxIterations`는 호환용으로 남아있으나 동작에 영향을 주지 않는다(`docs/memory.md`).

## 버전 메모리와 복원

Dream이 장기 파일을 바꾸면 `GitStore`가 그 변경을 커밋한다. 이로써 `/dream-log`(변경 조회), `/dream-restore`(이전 상태 복원)가 가능해진다(`nanobot/command/builtin.py`의 `cmd_dream_log`, `cmd_dream_restore`).
