# 3.2 Agent Runner and LLM Provider Interface (에이전트 러너와 LLM 프로바이더 인터페이스)

`nanobot/agent/runner.py`의 `AgentRunner`는 "제품 레이어 관심사 없이 도구를 쓸 수 있는 LLM 루프"를 실행한다. 프로바이더 호출, 스트리밍, 도구 실행, 결과 재투입을 반복한다.

## 실행 명세와 결과

- `@dataclass AgentRunSpec` — 한 번의 실행 설정. 주요 필드: `initial_messages`, `tools`(`ToolRegistry`), `model`, `max_iterations`, `max_tool_result_chars`, `temperature`, `max_tokens`, `reasoning_effort`, `hook`, `concurrent_tools`, `fail_on_tool_error`, `workspace`, `session_key`, `context_window_tokens`, `context_block_limit`, `provider_retry_mode`, 각종 콜백(`progress_callback`, `retry_wait_callback`, `checkpoint_callback`, `injection_callback`), `llm_timeout_s`, `goal_active_predicate`, `goal_continue_message`, `finalize_on_max_iterations`.
- `@dataclass(slots=True) AgentRunResult` — 결과. `final_content`, `messages`, `tools_used`, `usage`, `stop_reason`(기본 `"completed"`), `error`, `tool_events`, `had_injections`.

## 실행 흐름

- `run(spec)` — 진입점. 내부적으로 `_run_core`를 호출.
- `_run_core(...)` — 반복 루프의 본체. 각 반복에서:
  1. `_build_request_kwargs`로 요청 인자를 만들고 `_request_model`로 프로바이더에 요청(스트리밍 포함).
  2. 응답에 도구 호출이 있으면 `_execute_tools` → `_run_tool`로 실행하고 결과 메시지를 추가.
  3. 주입(injection)을 배수(`_drain_injections`, `_try_drain_injections`)해 사용자·목표 지속 메시지를 이어붙임.
  4. 도구 호출이 없고 최종 콘텐츠가 있으면 종료.
- 반복 한계 도달 시: `finalize_on_max_iterations`가 참이면 `_try_finalize_after_max_iterations` / `_request_finalization_retry` / `_request_no_tools`로 마지막 답을 유도. 아니면 `_max_iterations_fallback` 메시지를 사용.

## 주입(Injection)과 목표 지속

턴이 도는 도중에 새 사용자 메시지나 "목표 계속" 신호가 들어올 수 있다.

- `_drain_injections(spec)` — `injection_callback`으로 대기 중인 주입을 가져옴.
- `_append_injected_messages` — role 교대(user/assistant)를 유지하며 주입을 병합/추가. 연속된 user 메시지는 `_merge_message_content`로 합침.
- `_build_goal_continue_message` — `goal_active_predicate()`가 참이면 목표 지속 메시지를 생성해 장기 작업을 이어감([12.1 long-goal](12.1-built-in-skills-reference.md)).
- 주입 사이클은 `_MAX_INJECTION_CYCLES`로 제한된다.

## 도구 실행

- `_execute_tools(...)` — 배치 단위로 도구를 실행. `_partition_tool_batches`가 동시 실행 가능(`concurrency_safe`)·배타적(`exclusive`) 도구를 분리한다.
- `_run_tool(...)` — 개별 도구 호출. 예외/에러 결과를 분류(`_classify_violation`, `_is_ssrf_violation`, `_is_workspace_violation`)해 SSRF/워크스페이스 위반을 부드럽게 처리(`_ssrf_soft_payload`).
- `_drop_malformed_tool_calls`, `_malformed_tool_call_retry_messages` — 형식이 깨진 도구 호출 복구.
- `_emit_checkpoint` — 진행 중 상태 체크포인트([4.1 runtime checkpoint](04.1-session-manager.md)).

## 사용량 집계

토큰 사용량은 여러 헬퍼로 병합·추정된다: `_usage_or_estimate`, `_estimate_response_usage`, `_usage_dict`, `_accumulate_usage`, `_merge_usage`, `_usage_total`.

## LLM 프로바이더 인터페이스 (`nanobot/providers/base.py`)

러너는 구체 프로바이더를 몰라도 되도록 추상 인터페이스 `LLMProvider(ABC)`에만 의존한다.

핵심 타입:

- `LLMResponse` — 응답. `has_tool_calls()`, `should_execute_tools()`.
- `ToolCallRequest` — 모델이 요청한 도구 호출. `has_valid_name()`, `to_openai_tool_call()`.
- `GenerationSettings` — 생성 파라미터(temperature, max_tokens, reasoning_effort).
- 파싱 헬퍼: `parse_tool_arguments`, `tool_arguments_object_for_replay`, `tool_arguments_json_for_replay`.

`LLMProvider`가 정의하는 계약(발췌):

- `chat(**kwargs)` — 비스트리밍 요청(추상).
- `chat_stream(**kwargs)` — 스트리밍 요청.
- `chat_with_retry` / `chat_stream_with_retry` — 재시도 래퍼. `_run_with_retry`가 백오프, 429/일시 오류(`_is_transient_error`, `_is_retryable_429_response`), `Retry-After` 헤더 파싱(`_extract_retry_after*`), heartbeat 슬립(`_sleep_with_heartbeat`)을 처리.
- 메시지 위생 처리: `_sanitize_empty_content`, `_sanitize_request_messages`, `_enforce_role_alternation`, `_strip_image_content`.
- `get_default_model()`.

구체 구현은 [5. LLM Providers](05-llm-providers.md)에서 다룬다.
