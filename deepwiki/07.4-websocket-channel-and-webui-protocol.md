# 7.4 WebSocket Channel and WebUI Protocol (WebSocket 채널과 WebUI 프로토콜)

`nanobot/channels/websocket.py`의 `WebSocketChannel`은 특별한 채널이다. nanobot이 **WebSocket 서버**로 동작해 연결된 클라이언트(주로 WebUI, [9](09-webui.md))에 서비스한다. 기본 포트는 `8765`.

## 설정과 시작

`WebSocketConfig`(`Base` 상속)로 설정한다.

- 바인드 host/port, 경로.
- 인증 토큰과 로컬/원격 정책.
- TLS(선택): `ssl` 컨텍스트 구성.
- Unix 소켓 서빙(`unix_serve`)도 지원.

서버는 `websockets` 라이브러리(`serve`/`unix_serve`, `ServerConnection`)로 구동된다.

## 인증

- 로컬 연결과 원격 연결을 구분한다. 원격 접속은 토큰을 요구하며 `hmac` 비교로 상수 시간 검증한다.
- 워크스페이스 스코프: 연결마다 워크스페이스 접근 범위를 결정한다(`WorkspaceScope`, `WORKSPACE_SCOPE_METADATA_KEY`, [11.2](11.2-workspace-policy-and-sandboxing.md)). 원격 클라이언트는 제한된 스코프를 받을 수 있다.

## 멀티플렉스 프로토콜

하나의 WebSocket 연결로 여러 채팅(chat)을 동시에 다룬다.

- 각 프레임은 JSON envelope다. `chat_id`로 멀티플렉스된 대화를 구분한다.
- 인바운드: 클라이언트 메시지를 파싱해 `InboundMessage`로 버스에 발행. 이미지 등은 base64 data URL로 오며 `save_base64_data_url`로 저장(`FileSizeExceeded` 제한).
- 아웃바운드: `OutboundMessage`와 구조화 이벤트를 클라이언트로 전송.

## 이벤트 프로토콜

`nanobot/bus/outbound_events.py`가 정의하는 구조화 이벤트를 WebSocket 프레임으로 변환한다(`outbound_event_from_message`, `outbound_message_for_event`).

| 이벤트 | 의미 |
|---|---|
| `ready` | 연결 준비 완료 |
| `message` / delta | 최종/스트리밍 텍스트 |
| `ProgressEvent` | 진행 상황(도구 실행 등) |
| `TurnEndEvent` | 턴 종료 |
| `SessionUpdatedEvent` | 세션 갱신(사이드바 동기화) |
| `GoalStateSyncEvent`, `GoalStatusEvent` | 장기 목표 상태([4.1](04.1-session-manager.md)의 `goal_state_ws_blob`) |
| `RuntimeModelUpdatedEvent` | 런타임 모델 전환 알림 |

스트리밍은 델타 프레임을 연속 전송하고 turn 종료 시 종료 프레임을 보낸다(`docs/websocket.md`의 `ready`/`message`/`delta`/`stream_end`).

## WebUI 전용 연동

WebSocket 채널은 순수 채팅을 넘어 WebUI 백엔드 기능과 결합되어 있다([9.2](09.2-backend-webui-apis.md)).

- 세션 관리: 세션 목록/포크(`handle_webui_fork_chat`, `nanobot/webui/forking.py`).
- CLI 앱/MCP 프리셋 멘션 정규화(`normalize_cli_app_mentions`, `normalize_mcp_preset_mentions`).
- 전사: `webui_transcription_event`(음성 입력).
- 게이트웨이 서비스: `GatewayServices`(`nanobot/webui/gateway_services.py`)를 통해 런타임 제어.
- 미디어 저장: `get_media_dir`.

## TLS와 보안

원격 노출 시에는 TLS와 토큰 인증을 함께 써야 한다(`docs/websocket.md`, `docs/deployment.md`). 인증 없이 `0.0.0.0`에 노출하는 구성은 위험하므로, 배포 시 리버스 프록시/TLS/토큰을 권장한다([13.1](13.1-docker-and-container-deployment.md)).
