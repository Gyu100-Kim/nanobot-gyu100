# 13.2 Testing and CI (테스트와 CI)

## 로컬 테스트/린트

`AGENTS.md`와 `pyproject.toml` 기준.

```bash
# 파이썬
pytest tests/test_openai_api.py::test_function -v   # 단일 테스트
ruff check nanobot/                                  # 린트

# WebUI (Bun)
cd webui && bun run test
cd webui && bun run lint
cd webui && bun run build
```

- pytest 설정: `asyncio_mode = "auto"`, `testpaths = ["tests"]`(`pyproject.toml`). 테스트는 `nanobot/` 패키지 구조를 미러링한다.
- ruff 설정: `line-length = 100`, `target-version = "py311"`, `select = ["E","F","I","N","W"]`, `ignore = ["E501"]`.

## CI (`.github/workflows/ci.yml`)

워크플로 이름은 `Test Suite`. 트리거는 `main` 브랜치 push/PR이며 **`docs/**` 경로는 무시**된다(`paths-ignore`). 이 위키는 `deepwiki/**`에 있어 무시 목록에 포함되지 않으므로, 문서 변경이라도 CI가 실행된다.

### `test` 잡

- 매트릭스: OS `ubuntu-latest` / `windows-latest` × Python `3.13` / `3.14`.
- 시스템 의존성(Linux): `libolm-dev build-essential`.
- 단계:
  ```bash
  uv sync --all-extras --dev
  uv run ruff check nanobot --select F
  uv run python -m pytest tests/ --cov=nanobot --cov-report=term-missing:skip-covered
  ```
- 주의: CI 린트는 `--select F`만 검사한다(런타임 오류 위주). 로컬 `ruff check nanobot/`은 `E,F,I,N,W`를 모두 본다.

### `webui` 잡

- Bun `1.3.6` 사용.
- 단계:
  ```bash
  cd webui && bun install
  cd webui && bun run lint      # eslint src --max-warnings 0
  cd webui && bun run test      # vitest run
  cd webui && bun run build     # tsc + vite build
  ```

## 이 위키 변경에 대한 검증

`deepwiki/`는 Markdown 문서만 추가하므로 애플리케이션 코드/테스트에 영향이 없다. 문서 지향 검증으로 충분하다.

- `git diff --check` — 공백/충돌 마커 검사.
- 상대 링크 정합성 확인(모든 `deepwiki/*.md` 링크가 실제 파일을 가리키는지).
- 다만 위 CI가 `deepwiki/**`에서도 트리거되므로, 파이썬/WebUI 전체 스위트가 돌아 회귀가 없는지 확인된다.

### 참조 파일

- `.github/workflows/ci.yml`
- `pyproject.toml` (`[tool.ruff]`, `[tool.pytest.ini_options]`)
- `AGENTS.md`, `tests/`
